The selected extraction worker links the bridge to the official NanaZip 7.0.1882.0 DLLs at runtime. The interface headers in `vendor/SevenZip` and their license are copied from the [upstream source](https://github.com/M2Team/NanaZip/tree/7.0.1882.0). Their archive SHA-256 is `413c4a3510d7e4c5c0e705d3a5c8a590cf9fcdbc5b6ffb5781275854354da67d`.

For numeric split 7z archives, the worker accepts unencrypted non-solid Copy or a single LZMA2 coder per block. LZMA2 blocks may contain one or several files. The bridge asks the official handler to extract every item and supplies a discard stream for each unselected file. Each selected file stays private until every item completes and the archive closes successfully.

Encrypted split archives use the existing console backend and its anonymous password input pipe. Adding them to this worker would require `ICryptoGetTextPassword` during both header opening and content decoding, plus a bounded private input channel for the isolated worker. Acceptance would cover encrypted headers and data, correct, wrong, missing and Unicode passwords, cancellation during header and data processing, and a corrupt unselected item. Passwords must stay out of process arguments, environment variables, temporary files and diagnostics.
