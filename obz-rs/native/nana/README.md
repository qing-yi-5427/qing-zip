The selected extraction worker links the bridge to the official NanaZip 7.0.1882.0 DLLs at runtime. The interface headers in `vendor/SevenZip` and their license are copied from the [upstream source](https://github.com/M2Team/NanaZip/tree/7.0.1882.0). Their archive SHA-256 is `413c4a3510d7e4c5c0e705d3a5c8a590cf9fcdbc5b6ffb5781275854354da67d`.

For numeric split 7z archives, the worker accepts unencrypted non-solid Copy blocks. It also accepts single-coder LZMA and LZMA2 blocks, including solid blocks and blocks wrapped in 7z AES encryption. The bridge asks the official handler to extract every item and supplies a discard stream for each unselected file. Each selected file stays private until every item completes and the archive closes successfully.

For supported AES-encrypted blocks, the inner 7z open and extraction callbacks provide the password through the official `ICryptoGetTextPassword` interface. An anonymous input frame carries up to 32,767 UTF-16 code units to the isolated worker, which erases its transport buffer. The codec owns each returned BSTR. Other encryption/filter chains and longer passwords continue through the existing console input pipe. Active machine policy uses the official policy-controlled backend.
