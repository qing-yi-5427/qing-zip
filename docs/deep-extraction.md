# 深度解压

将文件拖到首页「深度解压」区域即可添加到批量窗口。也可点击该区域、从工具箱进入「批量深度解压」，或在已有压缩包的解压窗口打开「深度解压」。批量窗口可填写多行路径、选择文件，或拖入多个文件。分卷放在同一目录，选择其中一卷即可定位第一卷。

程序按文件内容识别 ZIP、7z、RAR、TAR、GZip、BZip2、XZ，也检查 ZIP 末尾记录和有限的自解压头部，因此支持无后缀、改名和常见带前缀的压缩包。识别后仍由现有引擎校验，候选特征本身不代表归档有效。Office、APK、JAR、EPUB 等应用或文档容器依据扩展名与内部结构保持完整。

缺少第一卷时会暂停并提示所需文件名。文件名相似不能证明同属分卷；无法确认的同名匹配文件会完整保留，并在任务中列出，不凭文件名删除。

布局示例：

- `资料.jpg → 第一层.7z → 第二层.zip → 照片/a.jpg` 保存为 `资料/照片/a.jpg`。只收起压缩包套娃，不移除最终文件夹。
- 外包同时包含 `readme.txt` 和 `inner.zip` 时，保留 `readme.txt`，并将内层内容保存到 `inner`。若内层本来已有同名目录，不再生成 `inner/inner`。
- 选定范围解压只继续展开选中的输出；所有条目仍做路径和命名空间校验，外层目录可读取时，只选中未加密条目无需密码；程序解码并校验选中的内容。

批量解压时，「保存到」留空即可在各原包所在目录分别创建专属输出文件夹；填写后，同批结果都保存到指定位置。智能解压默认开启，包内已有同名顶层目录时直接使用这一层。若无后缀原包或现有目录占用了名称，输出文件夹会自动编号，例如 `资料 (2)`。任务会列出实际输出路径。

## 密码、失败与取消

可在批量窗口预填密码，原包和内层压缩包会尝试使用它。遇到密码、分卷或限制问题时，任务显示待处理项目及其完整来源层级，可以为该分支输入密码重试、提高限制，或保留此包继续。已成功解压的结果会复用。密码仅用于本次会话。

每个原包的结果就绪后独立保存。某个原包或其内层分支暂停时，同批其他原包仍可保存并出现在任务报告中。待处理项目完成或明确保留后，继续保存该原包的结果。任务页和任务记录均可重新打开会话。

首页和工具箱共用的批量窗口提供「全部成功后将原包移入回收站」，首次默认关闭。开启后，程序先校验并保存所有结果，再对原包逐项复核单卷状态和来源身份。取消、跳过、部分完成、分卷或来源身份无法确认时保留原包。回收失败会列出保留的来源和原因。

保存遇到原包或分卷时，即使选择覆盖，也会保留恢复结果。中间压缩包只有在整个子树完整展开后才会从暂存目录移除。对于暂存区内的连续 `.7z.001`、`.7z.002` 等分卷，程序还会核对 7z 起始头、引擎报告的卷数和长度以及各卷的文件身份。无法确认的匹配文件仍保留在结果中。

取消或保存失败时，已保存文件保留，已校验的其余结果保留在恢复目录。任务提供「打开恢复目录」和「结束并保留恢复目录」。应用退出后仍可直接从该目录取回文件；自动续传会话仅在本次应用运行期间有效。保存重试逐项确认已经保存的目标，避免改名策略重复复制；无法确认的目标会停止自动重试并保留恢复数据。

## 限制与恢复位置

高级设置默认：最多 8 层、256 个压缩包、累计 100000 个文件、20 GiB 处理预算、磁盘保留 1 GiB。大文件可以提高处理预算。层数从原包记为 1；压缩 TAR 会先解开外层流，再处理 TAR，因此占用两层。压缩包数量按不同归档计算，重试不重复计数。

处理预算采用保守计费：已知大小按选定条目的声明大小预检，解压后核对实际暂存结果；失败尝试也按至少完整选定声明大小计入。原始压缩流通过固定大小缓冲区写入，超过剩余预算前停止。中间 TAR 和密码重试都计入预算。

这不是所有格式的统一硬性磁盘写入上限：现有归档引擎内部的暂存与未选数据校验仍遵循原有策略，失败内部工作量使用上述保守估算。原始流的写入量则有实际限制。空间预检通过后，外部程序仍可能占用磁盘；发生空间不足时保留原包和可恢复结果。

恢复位置默认在本机应用数据目录的 `qing-zip/DeepRecovery`。开始任务前可选择容量更充足的目录。当前会话使用创建时的位置；调整这个设置用于后续新会话。恢复目录不会保存输入过的密码。
