# Windows 性能基线

2026-11-23 · qing-zip 0.12.23 · 源码 `0cc51aa2379321361012f32515edb40b95e2ebf9`。

这份基线记录 Windows x64 加固便携包中 `obz.exe` 的归档操作，以及工具箱所调用的 LZMA 合成基准。四类样本全部完成创建、列出、校验、解压，源目录、源归档与解压结果通过目录树和 SHA-256 比较。

## 第三轮 ZIP 更新与任务卡

托管 Windows x64 build 26100、WebView2 157、1028 × 779 视口、100% 缩放。以原版、候选、候选、原版的顺序启动四次应用，每次先触发一次满盘错误预热，再点五次保存。计时从实际点击事件到 WebView 第一次可见失败卡片的动画帧，包含真实写回请求。原版十次中位 60.75 毫秒（56.5–67.7），候选十次中位 58.90 毫秒（54.9–63.0）。按轮次和会话内序号对齐后，差值中位 −1.80 毫秒，范围 −12.6 至 +0.1 毫秒。四个会话都保全原包和工作副本，释放空间后成功写回。此测量覆盖热会话中的该错误反馈，未测冷启动、物理屏幕呈现或 GPU 耗时。[同机实测](https://github.com/qing-yi-5427/qing-zip/actions/runs/45131491561)

本机 Windows 11 x64 build 26300 使用同一 NanaZip 引擎比较两份加固 CLI。普通 ZIP 添加 1 KiB 成员时，12 对交替执行的中位耗时为 93.910 和 93.678 毫秒，逐对差值中位为 +0.537 毫秒，范围 −4.152 至 +9.676。添加 16 MiB 时，8 对中位耗时为 400.567 和 400.990 毫秒，逐对差值中位为 +1.282 毫秒，范围 −8.753 至 +15.487。每轮独立校验成员和输入哈希。中断后另用进程写入计数实测，候选在父进程退出采样点之后的计数增长为零。普通操作耗时的差值两个方向都有。[计时与中断回执](https://github.com/qing-yi-5427/qing-zip/tree/4b2286ff0532cb1f49d045dbf027cc6d9a9fd9f3/docs/verification/zip-update-owned-job)

同一进程的两个工作线程分别更新两个独立 ZIP，1 KiB/包测 10 对，8 MiB/包测 8 对。两项更新全部完成的中位耗时分别从 65.428 到 64.954 毫秒、236.202 到 237.965 毫秒。逐对差值的中位分别为 −0.387 和 −1.474 毫秒，范围分别为 −2.344 至 +5.236、−16.446 至 +20.700。每次核对两份归档的成员与来源，8 MiB 预热还在两个版本分别观察到同时运行的两个写入引擎。此抽查覆盖后台并发更新。[构建与逐轮数据](verification/round3/concurrent-update/README.md)

同机 Ryzen 7 9800X3D、Node 24.14 下，测量实际任务卡函数生成 HTML 字符串的耗时。先预热两对，再交替执行 11 对，每个样本 4,000 次。完成卡片的逐对中位差值为 +0.020 微秒（−0.149 至 +0.099），失败卡片为 +0.089 微秒（−0.193 至 +0.162）。前端源文件增加 935 字节。此项只覆盖字符串生成，WebView2 的窗口布局、绘制、冷启动和 GPU 用量仍需分别测量。[逐轮测量](verification/nested-feedback-timings.json) · [实际失败和重试窗口](https://github.com/qing-yi-5427/qing-zip/tree/af2045c73c10f402a8239d1b34399658f8e21a9f/docs/verification/nested-save-capacity)

## 环境与计时

- Windows 11 Pro x64 build 26300，AMD Ryzen 7 9800X3D（8 核 / 16 线程），48 GiB RAM，Solidigm SSDPFKKW020X7 2 TB NVMe。便携程序在 `G:`，合成输入与输出由 Python 在同一物理 SSD 的 `%TEMP%` 下创建。
- Release 目标为 `x86_64-pc-windows-msvc`，Rust 1.99.0。宿主 Python 3.14.0，包内 NanaZip 7.0.1882.0，独立互读使用包内官方 7-Zip 26.06。
- 测量用 `obz.exe` SHA-256 为 `b0f30fb6440caf0bd98cb67fc448adfcdaa6cf4903f79c20f310584ce09277f9`。整包 SHA-256、PE 审计范围与实跑命令见 [测试矩阵](TEST_MATRIX.md)。
- 每种数据先预热一轮，再串行测五轮。每项 CLI 操作启动一个进程，使用新归档路径和新解压目录。源数据在各轮复用，Windows 文件缓存保持自然状态，归档哈希在列表前读取。计时从 Python 发起进程到返回并接收完输出，包含子进程启动、引擎、文件 I/O 和 CLI 响应传输。JSON 校验、样本生成和 SHA-256 比较在计时外，时间属性和访问控制列表不在校验范围内。
- 这里的每次启动都使用新 CLI 进程。真正的磁盘冷读、前台首次可交互、WebView2 内存和 GUI 预览尚未纳入本轮计时。

## 合成文件的实际归档操作

ZIP 使用 Deflate 等级 5，7z 使用固实 LZMA2 等级 5。创建、校验和解压传入 `--threads 4`，各后端实际并行度由引擎决定。表中耗时为第二组五次样本的中位数（最小–最大），单位毫秒。这次从 09:54:23 到 09:55:12（UTC+8），24 个主机采样均未观察到编译进程，系统总 CPU 为 16%–46%（平均 28%，含基准本身）。

| 样本 | 文件数 / 原始字节 | 包字节 | 创建 | 列出 | 完整性检查 | 全量解压 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 中文、空目录的微小 ZIP | 2 / 896 | 780 | 80（75–81） | 59（58–65） | 68（67–68） | 67（65–73） |

| 文本与伪随机数据混合的固实 7z | 64 / 7,010,304 | 4,238,934 | 244（241–254） | 66（61–71） | 119（114–126） | 162（161–165） |

首组使用相同二进制和负载配置，采样时有其他 Rust 编译运行，期间三次总 CPU 为 51%–67%。该组区间更宽，千文件解压为 900 ms（808–1,692 ms，预热 3,613 ms），微小 ZIP 创建为 185 ms（109–938 ms）。优化优先观察小文件解压。无编译采样中，约 4 MiB 的千文件样本耗时仍是 32 MiB 四文件样本的约 7.6 倍。需要阶段计时才能定位文件枚举、验证、路径处理和发布各自的成本。

## 普通解压冲突修复前后

对同一份普通 ZIP 交替运行 0.12.23 基线与修复后的 Release CLI。每个场景两次预热，随后每版 12 次，每次使用新的输出目录，检查实际文件数、每个输出的字节、预置文件和原始 ZIP 的 SHA-256。计时包括进程启动和解压，不包括生成样本或事后校验。两版 CLI 的 SHA-256 前缀分别为 `f69a7676f33f` 和 `909f16561120`。[解压修复](https://github.com/qing-yi-5427/qing-zip/pull/2)

## 复现与后续采样

```powershell
$build = ./scripts/build-hardened.ps1
$output = Join-Path $PWD ('dist/quality-' + [guid]::NewGuid())
python scripts/package.py --binary-directory $build.BinaryDirectory --output-directory $output
$receipt = Join-Path $env:TEMP ('qing-zip-perf-' + [guid]::NewGuid() + '.json')
python scripts/check-archive-interop.py `
    --cli "$output/qing-zip-0.12.23-portable/obz.exe" --rounds 5 --receipt $receipt
```

脚本生成固定数据的普通文件样本，记录每轮耗时、预热、范围、归档大小和互读 SHA-256。省略 `--rounds` 时仅运行互读。查看 [归档互读与测量脚本](../scripts/check-archive-interop.py)。

仓库的前台基准使用 `compare-final-desktops.py` 与 `bind-final-desktops.py`，绑定候选包、参考程序和固定 ZIP，以可见 UI Automation 内容为就绪口径，并采样进程树内存。该脚本限定可丢弃的 hosted Windows 环境，本轮标记 `NOT RUN`。吞吐归档样本和合成引擎输出均使用本机 CLI。查看 [前台测量脚本](../scripts/compare-final-desktops.py) 与 [输入绑定脚本](../scripts/bind-final-desktops.py)。

回归比较时固定数据、线程、档案设置、存储位置与系统负载，交替执行两个精确版本，同时报告范围及预热。GUI 启动、预览与内存单独比较，在相同 DPI、显示状态与 WebView2 版本下记录从操作到可交互的耗时及进程树私有提交内存。
