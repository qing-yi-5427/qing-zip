# 按用户价值排序的优化路线

本轮从本地 0.12.23（`0cc51aa`）出发。0.13–0.16 是组织工作的阶段，具体版本号随发行计划确定。

| 顺序 | 工作与理由 | 可交付边界 |
| --- | --- | --- |
| 1 · 可靠性（0.13） | 修复普通解压的名称冲突。用户选择自动改名时，一个冲突项会挤占另一个正常条目的原名；同名目录也会中止可跳过的普通文件。 | 在同一临时输出目录预置有内容的文件或目录，检查归档各条目的实际名称、内容和保留项。覆盖选择性提取及大小写匹配。 |
| 2 · 主力体验（0.13） | 对照主窗口、首页、资源管理器、批量和深度解压的目的地。重点看单顶层、多顶层、已有同名目录、选定条目。先记录差异是否来自用户的明确选择。 | 表格同时列出预告位置、实际位置和任务完成入口。中断或重试时记录原包、已发布内容和恢复位置，再决定要调整哪一个入口。 |
| 3 · 材质与可读性（0.14） | 从高频菜单开始统一短时浮层，保留明暗、实色与 Windows 10 回退。现有列表、任务和弹窗结构继续使用。 | 每轮只调整能在实际窗口看出差异的组件；通过实机截图、键盘操作、窗口尺寸、主题和响应数据验收。 |
| 4 · 原生入口与性能（0.15） | 验证现有 qing-shell、包身份和安装生命周期；复用智能解压及文件压缩协议。以实际等待时间决定列表、搜索和提取的优化先后。 | 真实一级菜单显示、点击转交与升级卸载均有证据后才进入安装链路。性能报告按样本、冷暖缓存和中位数区分。[Explorer 组件说明](../qing-shell/README.md) |
| 5 · 长期稳定性（0.16） | 在可恢复环境覆盖资源耗尽、长时间多任务、异常退出、升级、嵌套归档写回和恢复。 | 检查哈希、临时磁盘峰值与回收、重复执行的一致性；按系统和架构记录结果。 |

## 当前能力和取舍

| 分类 | 本轮判断 |
| --- | --- |
| 已实现，保留 | 小包打开、列表和树虚拟化、密码本、压缩高级设置、任务记录、深度解压恢复及内层写回均有既有实现。具体实测范围见测试矩阵。 |
| 已实现，优化 | 处理输出冲突、预告实际目的地、高频菜单材质。每次改动以一个可复现的任务为单位。 |
| 已有组件，尚待交付 | Windows 11 一级菜单已有 COM 组件和稀疏包脚本。优先确认真实平台架构和菜单生命周期。 |
| 尚未覆盖，价值高 | 稳定复跑的常见格式引擎互读、选择性解压与原包哈希核验，以及按入口对照最终路径。已有规模跑分继续区分诊断值与端到端结果。 |
| 暂不投入 | 新增长尾格式引擎、为每种冲突添加单独的偏好开关、给整张文件列表叠加模糊。 |

实现、验证与欠项分别记在[质量报告](QUALITY_REPORT.md)、[测试矩阵](TEST_MATRIX.md)和[性能报告](PERFORMANCE_REPORT.md)。
