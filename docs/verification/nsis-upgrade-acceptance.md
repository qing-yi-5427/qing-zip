# 一次性 Windows x64 安装、升级与卸载验收

此验收仅由 GitHub 托管的一次性 Windows x64 runner 执行。**提交脚本或通过本机拒绝测试不等于安装验收通过**；实际结果以本 PR 的 `Disposable Windows NSIS upgrade acceptance` 作业与 artifact 中的收据为准。

仓库的 v0.12.20 与当前 NSIS 脚本均采用每用户安装，并支持用最后的 `/D=` 覆盖安装目录。测试创建仅属于本次运行的 `RUNNER_TEMP` 子目录，要求路径无需引号且不存在既有 qing-zip 注册，再将旧版与候选都指向其中同一目录。如果这些前提不满足则直接失败，不转而安装到默认目录。安装器仍会在当前用户 HKCU 与开始菜单登记，因此不能在真实用户设备运行；runner 环境变量只是防误用检查，并非密码学证明。

工作流固定上一正式版 v0.12.20，下载并校验 GitHub 发行资产：安装器 SHA-256 `83a08671edde7bb53ff37582f4d82fd880c968029ddcd39001119efc11a979e1`、便携包 SHA-256 `6acef9b5a4ae726b6e6bd9bad4eecda5b4238d5f60296cc4b5d74e7671efb84a`。固定 NSIS 3.13 上游包哈希，并调用仓库 `scripts/build.ps1` 构建同次源码的 0.12.23 加固候选安装器与便携目录。不创建证书、不签名 MSIX、不发布 Release。

验收流程：

1. 静默安装旧版到临时路径；核对注册版本、可执行文件 PE 版本、路径、开始菜单快捷方式，以及旧版三个可执行文件与已校验便携包一致。
2. 用已安装的旧版 CLI 创建普通 ZIP，在安装目录内放归档和无关文件，在目录外放另一哨兵与合成来源；记录哈希。
3. 原位安装候选，核对注册版本、可执行文件 PE 版本和完整候选便携文件清单的哈希，核对旧归档、来源及哨兵未变；用新版 CLI 测试并解压旧归档，核对解压输出。
4. 静默卸载，等待卸载器和产品注册消失，核对候选程序文件和所建快捷方式移除，安装目录仅剩测试创建的归档与哨兵，目录外来源、解压结果与哨兵内容不变；核验后仅清理本次拥有的临时根。

`nsis-upgrade-acceptance-evidence` artifact 保留构建与 PE 记录和 `acceptance/receipt.json`。脚本逐步写入检查点；失败时仅在注册路径确为本次目标时尝试其卸载器，若无法安全卸载则不强行删除安装根，由一次性 runner 回收。构建、下载或环境检查提前失败时，artifact 可能只有初始记录；这不构成通过。没有覆盖默认安装目录、真实用户配置、文件关联或 Explorer 右键注册、重启恢复及特殊文件系统。

首次托管运行已通过旧版安装、原位升级和升级后解压，但卸载后“仅余合成用户文件”检查失败。首次收据没有记录额外文件的具体名称，不能推断原因；后续收据会记录相对名称、哈希及其是否与旧发行包中的文件完全一致，不会自动删除这些额外文件。详见 [首次作业](https://github.com/qing-yi-5427/qing-zip/actions/runs/45110662819)。

本机只运行 `python scripts/test-hosted-installer-guard.py` 验证非托管环境会在访问安装器前拒绝执行；安装/卸载脚本必须由上述托管工作流执行。
