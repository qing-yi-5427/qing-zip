# 异常退出后的未发布候选：设计决策

**暂不自动删除既有候选，也不直接把 Job Object 加到生产进程启动路径。** 下一步先验证“控制端退出后停止其专属引擎”的进程生命周期方案；回收旧产物需要另行设计和证明。该决定建立在 `51a68cc` 源码、[#10 的三轮普通 ZIP 中断实测](https://github.com/qing-yi-5427/qing-zip/pull/10)及下面的独立机制实验上。

## 现有状态与无法判定的边界

| 时点 | 具体状态 |
| --- | --- |
| 更新开始 | `update_lock` 使用 TEMP 下基于规范化目标路径的锁文件；`EditSource::open_controlled` 固定祖先、父目录及原包句柄，并保留拒绝写入的桥接句柄。不同 TEMP 环境不应假定共用这把锁。 |
| 产生候选 | `EditSource::output` 在原包旁创建私有 stage 和 `output` 目录并固定目录句柄；`update_impl` 随后启动引擎、检查候选。此时尚无 `edit-intent.dpapi`。进程意外终止不会执行 `PrivateStage::drop`；#10 观察到的子进程仍写入后留下候选，不能单凭名字判断已经安全。 |
| 提交前 | `commit_bound_with` 在检查目录、记录原件与候选对象身份后才调用 `Intent::write`，记录受 DPAPI 保护的父目录、stage、原件、候选身份及目标名称等信息，并同步写入。它持有 share-mode 0 的 marker 句柄，阻止其他实例把**这段时期**的活跃事务当作恢复目标；这不覆盖此前无 marker 的候选。 |
| 已取得原件后 | 原件被移入私有命名空间后，`PreserveOnDrop` 在异常退出或无法恢复时保留 stage。它可能包含唯一的原件、候选或需要用户查看的恢复数据；部分路径还会主动清空 marker 并保留目录。不可把 marker 缺失、为空或进程已经退出当作可删除凭据。 |
| 将来打开同一路径 | 读取失败后才尝试 `recover_missing`，且目标存在时立即返回；目标缺失时，才按 marker、DPAPI、父目录/stage/对象身份等核对，并尝试获取互斥 marker 句柄。无 marker 的早期候选不属于当前恢复协议；目标正常存在也不会触发对其分类或回收。 |

原包读取句柄、私有目录句柄及锁在控制端退出后不再由该控制端持有；子进程可能仍持有自己的句柄。新的同路径操作或释放的锁本身不能证明旧子进程已结束、stage 由该归档创建、其中没有保留原件，或可以删除。不同用途也共用私有 stage 机制。

## 最小机制实验

`scripts/probe-owned-job-lifetime.py` 在 Windows 11 26300、Python 3.14.0 上，只启动本测试的 Python 控制端、受控写入子进程及独立写入进程。控制端把受控子进程分配到设置 `KILL_ON_JOB_CLOSE` 的无名 Job Object 后，测试终止控制端。三轮受控子进程在 **2.8–3.1 ms** 内退出，随后 300 ms 文件增长为 0；独立进程持续运行且各增长 107,520 字节。逐轮数据见 [owned-job-probe.jsonl](owned-job-probe.jsonl)。测试仅针对自己创建的临时目录和精确进程句柄；结束时清理这些对象。

这是 Job Object 在该机器上的机制验证，**不是 qing-zip 或 NanaZip 的集成验证**。该实验先启动子进程再分配 Job，控制端在两者之间退出仍可能留下未受保护的子进程；不能因此直接将现有 `spawn` 后附加 Job 宣称为完整修复。即使未来能阻止孤儿继续写入，也不会自动删除已产生的候选或区分应保留的原件。

## 实施前提与验收

1. 设计只约束该操作所创建的引擎及其必要后代，不按名称寻找或终止全局进程。明确创建与归入受控生命周期之间的崩溃窗口、句柄继承、子进程及失败清理；对已有外层 Job、权限或平台不支持等情形定义安全失败行为，不能悄悄降级为未受控写入。若使用挂起创建再分配，必须单独处理分配前控制端退出后遗留的挂起进程；不能将其视为已解决。
2. 在可控的普通临时文件上分阶段终止测试自己的控制端：引擎创建前、创建与约束交接处、引擎读写中、校验中、intent 前后及发布/回滚交接处。核验受控子进程不再写入，独立作业不受影响，原件与用户输入可用，已有可恢复原件不会被删；分别记录成功、明确失败与未验证场景。验证支持的 Windows 版本及已处于其他 Job 的运行环境。
3. 回收策略另提协议与审查：在候选创建前持久绑定身份、归属和状态，且须可靠区分活动写入、未发布候选和任何故意保留的恢复原件；不以名称、年龄、目标存在或无 marker 为删除依据。老版本遗留目录缺少早期可验证记录，默认保留。需要更强边界的特殊文件系统、重解析及 ADS/TxF 场景只在获准的一次性隔离环境验证，不在本机扩展实验。

本设计不改变产品行为，不证明现有残留可安全自动回收。
