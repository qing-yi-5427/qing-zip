# 普通 ZIP / 7z 双任务长跑

该测试由路径限定的 `Bounded ordinary archive soak` 工作流在 GitHub 托管 Windows x64 runner 运行，先执行仓库的加固构建、运行时校验和便携包打包，再从同次生成的便携目录运行 CLI。工作流先做 5 秒烟测；正式测试请求至少 1,800 秒，保留实际耗时，失败或不足时长不标记通过。

每轮两项任务分别处理 ZIP 和 7z，使用不同输出目录，各限定 1 个压缩线程。每项任务校验并解压各自的种子原包，再创建、校验并解压新包，逐文件比较 SHA-256；每轮还复核共享中文路径来源和两份原包的哈希。任务开始使用屏障，并在同步检查点确认两条测试自己启动的 CLI 进程均未退出；记录对应操作与采样时间。这是短间隔进程存活采样，不是全程 CPU 并行证明。每轮后两项任务清理各自目录，轮与轮之间最多暂停 0.5 秒；整个运行区间内不断重复任务，并非声称两个进程 30 分钟从未中断。

测试使用约 1 MiB 合成随机数据和一份中文文本，每个任务只有普通文件；不设置系统配置或使用链接、特殊文件系统、故障注入与攻击样本。所有测试数据在独占临时根内，仅按当前测试创建的确切路径清理。输出摘要和逐轮 JSONL 位于测试根之外；中途普通错误会保存失败类型、完成轮数、逐项结果和清理状态，再以失败退出。硬终止或 runner 失联只能保留最后一次已写入的进度，不能声称完整清理或测试通过。

工作流的 `ordinary-archive-soak-evidence` artifact 包含来源及二进制哈希、加固构建和 PE 证明、烟测与正式测试的 `summary.json` / `rounds.jsonl`。摘要包括请求与实测时长、总任务及失败数、实际观察到进程重叠的轮数、来源和原包哈希以及临时根清理结果；逐轮记录新包与解压输出哈希、各操作耗时和清理结果。构建失败时仍上传已生成的初始证据；artifact 不存在或只有部分结果不能视为通过。托管 runner 是一次性环境，此项不是性能基准。

复现可在 Windows 上对一个完整可信便携目录执行：

```powershell
python scripts/soak-ordinary-archives.py --cli <portable>/obz.exe --out <new-evidence-directory> --duration-seconds 1800 --interval-seconds 0.5
```

本机 5 秒、256 KiB 输入的早期烟测仅验证脚本基本流程，不是长跑结果；最终以该 PR 对应运行的 artifact 和 `summary.json` 为准。

首次托管运行的 5 秒烟测收据记录 6 轮、12 项、零失败且临时根已清理，但脚本随后向 cp1252 控制台打印中文时异常退出，故该工作流失败、正式长跑没有开始。收据从 [首次运行 artifact](https://github.com/qing-yi-5427/qing-zip/actions/runs/45107685006) 保存；后续版本将控制台摘要转义为 ASCII，JSONL 仍为 UTF-8。该烟测不作为长跑通过证据。
