# 完整性校验随发起进程退出

Windows 11 x64、普通本地 NTFS。已安装的 c52c4ce 在更新普通 ZIP 时，外部完整性校验已开始后被强退。通过实际校验进程的句柄取样，三轮在编辑进程退出后又观察到 219–234 ms CPU 时间，经过 228–239 ms 校验进程才退出。候选复用既有 Windows 作业对象。三轮从观察到父进程退出到校验进程退出分别为 0.05、0.27、0.41 ms。Windows 的进程 CPU 计数以较粗粒度更新，第二轮还记录了一个 15.625 ms 计时单位。所有原包哈希保持。[原版三轮](verifier-current.jsonl) · [候选三轮](verifier-candidate.jsonl)

为了区分自动终止与自行跑完，回归测试先确认进程是本次 CLI 的直接子进程，且正在校验夹具的原包或同一夹具中新生成的候选。测试短暂挂起该子进程，再强退本次启动的 CLI。旧版两种场景都必须由测试恢复校验进程后才能退出；候选在校验进程仍被挂起时即可随父进程结束。检查还重新运行原操作，核对全部成员的名称及内容。[原版两项](verifier-baseline-gate.json) · [候选两项](verifier-candidate-gate.json)

另以合成密码核对 AES ZIP 和加密文件名的 7z，旧版与候选在正确密码时均成功、错误密码时均报错，原包哈希均保持。[八项结果](verifier-password-controls.json)

常规 Windows x64 和 ARM64 打包工作流均复跑 scripts/check-verifier-exit.py。另对普通 USTAR 选取解压在外部校验器启动时检查 Windows 作业对象，核对选中成员、未选成员、原包和同目录独立文件。该变更管理外部完整性校验进程的生命周期。已写完但尚未提交的候选文件回收另有独立问题。
