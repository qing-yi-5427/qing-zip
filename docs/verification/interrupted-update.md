# ZIP 更新异常中断与恢复实测

结论：**原包和来源在本次中断点保持完整，独立任务与重试均通过；临时产物未回收。** 这是一项普通 ZIP 文件的进程终止实验，不能推广为断电、系统崩溃或所有更新阶段均安全。

## 方法与边界

- Windows 11 26300，Python 3.14.0、psutil 7.2.2；被测为 #3（`51a68cc`）的 x64 0.12.23 便携版 CLI，SHA-256 `b0f30fb6440caf0bd98cb67fc448adfcdaa6cf4903f79c20f310584ce09277f9`；随包 NanaZip Console SHA-256 `06070ca08b3d10e760e8e394a1b6c8ad751aff89f759227ec111b878c12db139`。逐轮匿名记录见 [interrupted-update.jsonl](interrupted-update.jsonl)。
- 每轮在新建且由测试拥有的临时目录中创建一个含单个小文件的 ZIP、128 MiB 可重复随机输入，以及另一独立任务的 64 MiB 可重复随机输入。两项任务由各自 CLI 进程发起。
- 从待中止 CLI 的进程树观测 NanaZip `a` 更新子进程，检查参数匹配本轮原包及输入，且其累计读取至少 2 MiB、写入至少 1 MiB；同一采样循环也观测到独立 CLI 的 `a` 后代参数匹配独立输入且累计写入至少 1 MiB，并在终止前检查独立 CLI 仍在运行。进程 I/O 是整个进程的累计值，不证明每个字节的具体文件来源；两次后代采样相隔约 13–17 ms，不是同时硬件跟踪。
- 通过 `Popen.kill()` 强制终止待中止的 CLI 父进程，等待**已观察到的**后代退出，再重新打开原包、检查原包与输入 SHA-256、验证独立任务内容，最后重试并独立检查 ZIP 两个成员的内容哈希和输入哈希。未终止独立任务。脚本不扫用户目录，也不按前缀删除；测试结束只清理本次 `TemporaryDirectory` 创建的精确根目录。

## 三轮结果

| 检查 | 结果 |
| --- | --- |
| 原包打开和原包、来源哈希 | **PASS**，三轮均不变 |
| 独立创建任务 | **PASS**，中止前父进程仍运行，最终 ZIP 成员哈希均正确 |
| 解锁后重试 | **PASS**，原成员及新增成员哈希均正确；来源不变 |
| 归档旁临时产物 | **未回收**：三轮均为 1 个目录中的 1 个文件，134,218,001 字节；重新打开和重试后仍存在 |
| 测试 TEMP | **未回收**：三轮均为 1 个目录中的 2 个文件，共 564 字节；重新打开和重试后仍存在 |

从两项 CLI 启动计时，终止发生在 0.187–0.205 秒；终止之后已观察到的更新后代在 2.037–2.052 秒内退出。独立任务完成的观测上界为启动后 2.226–2.259 秒；该值包含等待更新后代，因此不是独立任务精确耗时。重新打开命令为 0.053–0.054 秒，重试命令为 2.324–2.503 秒。重试计时不包括测试脚本对 ZIP 成员的哈希校验。

留存大小是测试根目录在重新打开及重试后的扫描结果；该测试自己的临时根目录在收集结束后被清理。没有证明软件会在重启后回收这些产物，也没有证明所有后代都被采样到。早先 32 MiB 初步实验只以子进程读取量判断，未证明其正在更新或独立任务重叠，因此不作为上述结论依据。

## 复现

安装 `psutil`，提供匹配的完整便携版 `obz.exe` 和随包运行时；输出路径须不存在：

```powershell
python scripts/check-interrupted-archive-update.py --cli <portable>/obz.exe --out <new-receipt.jsonl>
```

需要足够的临时磁盘空间；每轮输入及归档都是测试创建的普通文件。若进程运行过快，未能观察到两个指定作业同时运行，脚本会失败，而不会把该轮标为通过。

## 最小后续建议

独立研究异常退出时的子进程生命周期，以及具备可验证所有权、活动占用检查和安全恢复语义的临时产物管理；先建立可丢弃测试环境中的故障注入与并发测试，再提出单独修复。不能依据目录名或前缀批量清理：无法仅凭名称证明属于本次操作、已无活动任务或没有需要保留的恢复数据。本 PR 不改变产品清理或恢复行为。
