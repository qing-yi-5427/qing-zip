使用原归档浏览基线的 10,000 和 50,000 文件普通 ZIP。各预热一对，再按相反顺序交替测三对。每轮以待打开归档作为参数启动真实便携应用的新进程，同一版本在本轮复用独立的临时 WebView 与本地数据目录。归档在轮间复用并核对 SHA-256，Windows 文件缓存保持自然状态。

首行口径是从发起进程到在真实 WebView DOM 中首次观察到已知首行位于可见滚动视口。计时包含 CDP 连接和探测延迟。其余动作从向同一实际窗口发送 CDP 鼠标或键盘输入到探测到相符的内容。每一轮确认窗口可见且未最小化，实测各次 Win32 前台焦点均为 `false`。因此这些读数覆盖应用报告的可见首行与真实 WebView 交互，系统前台可交互和从物理屏幕到首帧的验收仍待完成。

## 复跑

使用安装了 `pywin32` 和 `websockets` 的 Windows Python，测试时让各自的便携目录保留同架构运行时，并关闭已打开的同应用窗口。省略 `--allow-unfocused` 可要求真实 Win32 前台焦点。该开关只在会话无法自动取得前台时用于应用可见性记录。

```powershell
$envDir = Join-Path $env:TEMP ('qing-webview-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $envDir | Out-Null
python scripts/measure-webview-archive.py `
    --baseline '<本地起点便携包>/qing-zip.exe' --candidate '<组合便携包>/qing-zip.exe' `
    --rounds 3 --allow-unfocused --screenshots "$envDir/screens" --receipt "$envDir/timings.json"
```

逐轮数据记录了来源和样本哈希、预热、候选顺序、各次前台状态、可见行与挂载行数以及进程树内存。这个批次检查了浏览链路，选取解压和取消的实际证据来自独立便携 CLI 测试。[逐轮数据](webview-archive-browsing.json) · [归档性能报告](../PERFORMANCE_REPORT.md)
