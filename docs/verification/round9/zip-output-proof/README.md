本轮原型观察已经成功写入的候选字节。普通 Add 保留现有 NanaZip 随机访问输出。原生 Write、Seek、SetSize 报告实际位置。完整且连续写过的 256 KiB 范围形成 BLAKE3 摘要。被回写、截断、跳过的范围和尾部按候选的独占句柄重新读，单项回执保存所有原始字节的组合摘要。Rename 和 Delete 保留现有 NanaZip 控制台及其输出参数，在原始 stdout 字节落到同一候选的同时计算完整 BLAKE3。归档结果仍通过已有完整性校验和提交过程。

真正重开后的回收仍会在可信句柄下完整复算候选，继承 #56 的全部归属条件。独占句柄、目录及文件身份、DPAPI 认证、长度、同一公开归档和完整内容都须一致。没有可信证据时保留文件。已有事务非空记录继续优先处理。

## 其他交接设计

现有小 ZIP 校验先读取有上限的内存缓冲区，较大的 ZIP 交外部校验器。解出所有成员能核对成员内容，不能在原始 ZIP 的每个字节上提供相同序列的读取。校验器若仍按路径打开，无法和现有独占删除标记同时运行。调整到释放标记后才创建证据会重新暴露旧中断窗口。

权限租约涉及同账户文件所有者权益、旧校验器的路径读取以及 `ReplaceFileW` 对候选访问权限的要求。Windows 文件所有者默认仍有修改 DACL 的权限，收紧所有者权限会同时影响当前提交及异常后的处理。此原型沿用原提交权限，不以权限变化推断文件内容。[所有者 SID](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/understand-security-identifiers) · [ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)

在两个本地 NTFS 位置的普通临时文件上，仅查询文件和日志信息。解除待删除标记时序号未变，关闭写句柄并强读重开时两个文件的序号都变了，但内容和 ChangeTime 未变。其后普通写入再次改变序号。因此登记前的单个最近序号无法作为可靠的跨关闭证明。按文件读取的记录没有可信的 Reason 字段。跨活动日志代次、最后写入结束和正常权限的替代设计仍需另行验证。 [普通文件对照](usn-close-control.json) · [文件 USN 读取语义](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_read_file_usn_data)

Add 后续可测有界并行摘要。两块各 4 MiB 的缓冲区将把额外数据驻留限制在 8 MiB，加上已有块摘要表和线程状态。原生写完后把成功的真实偏移和数据交给摘要线程，同一块被回写及截断时按原顺序撤销旧证据。需要实测内存拷贝、队列反压和尾部等待的净成本，当前没有这些延迟或性能收益的实测结论。队列、证据或归属不可用时仍应能正常校验发布，并保留没有可靠证据的异常候选。
