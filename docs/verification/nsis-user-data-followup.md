# 卸载后用户数据哈希补测

这是一份历史回执。`Historical NSIS user-data follow-up` 只支持手动复跑，并固定检出 #20 的原始测试和源码。当前版本的静默安装与逐项哈希验收见 [一次性 Windows x64 安装、升级与卸载验收](nsis-upgrade-acceptance.md)。

冻结版 #19 的 [托管验收](https://github.com/qing-yi-5427/qing-zip/actions/runs/45112224372) 在全新旧版安装、升级、校验及解压后，确认 10 个旧版独有文件仍留存，严格的“仅余合成用户文件”检查因此失败。由于该断言位于卸载后的完整数据哈希检查之前，该次结果不能证明卸载后所有合成用户文件内容不变。

此补测在严格残留断言之前，分别记录并比较卸载前后的来源、原归档、解压输出、安装目录内哨兵、目录外哨兵 SHA-256。保留原有严格残留断言：即使五项数据完整，只要旧发行文件仍留存，整个验收仍为失败，不会通过删除这些文件来制造成功。

为避免重新编译产品，独立托管工作流下载 #3 已成功的同源码加固便携 artifact（run `45100520858`，head `51a68cc32bafcd535eac6cef8eee5169a54adcbe`），先确认当前产品与打包输入相对该提交无差异、构建结果为成功，并按同次 hardened-build 收据核验三个可执行文件。随后使用仓库 `package.py`、已验证运行时及固定 SHA 的 NSIS 3.13 重新打包安装器；这不是冻结版那一份安装器，补测收据记录其独立 SHA 和 GUI SHA。旧版 v0.12.20 setup 与 portable 仍使用固定发行资产 SHA 验证。

本补测只在一次性 GitHub 托管 Windows x64 运行，安装到新建临时路径；artifact 为 `nsis-user-data-followup-evidence`。工作流成功与否、五项哈希、剩余文件和清理状态均应从实际运行及收据核验。尚未运行或缺少收据时不能声称通过。
