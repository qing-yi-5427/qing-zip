# NSIS 0.12.20 旧文件恢复

从已登记的 x64 0.12.20 原位交互式升级到 0.12.23 时，安装器会在新文件放置完毕后核对旧安装登记。匹配固定发行清单的文件会进入可选检查。拒绝检查会保留全部原位置。检查中选择「否」保留该项，选择「取消」放弃本次选择。安装器会列出已移动与仍留在原位置的所选文件。

候选识别依赖旧版登记、固定相对路径、普通单链接对象、大小与官方文件 SHA-256。内容相同的用户替换文件也可能是候选，因此选择默认「否」。选择后会复核登记、文件身份与内容。仅以同卷句柄重命名移动匹配对象。恢复目录位于安装目录旁，保留原相对路径，且独立于卸载清单。用户可以在资源管理器中将文件移回原有路径，若已有同名文件则按需选择保留的位置。

静默安装、ARM64、登记不匹配、内容修改、不同相对路径的同名文件、无法固定的目录和对象均保留。现有安装器仍按当前发行清单卸载。历史版本未记录文件级归属，升级时不能补认领。以后若加入版本化收据，应从确实创建文件的那一刻记录安装目录和文件身份，与下次升级的当前对象逐项验证，并保留没有安全证据的项。[既有边界与十项发行证据](https://github.com/qing-yi-5427/qing-zip/pull/21)

## 托管验证

工作流 `Hosted NSIS retired-file migration` 仅使用一次性 GitHub 托管 Windows x64。对官方 v0.12.20 setup 和便携 ZIP 做固定 SHA-256 校验，再构建候选安装器。测试通过实际 NSIS 与确认窗口，覆盖静默、拒绝和选择两项迁移。检查同字节但不同文件身份的替换、已修改项、同名用户文件、原 ZIP、重复升级、卸载后保留及将文件恢复原位置。证据以 [对应 PR 的托管检查](https://github.com/qing-yi-5427/qing-zip/pull/27/checks) 中 `nsis-retired-migration-evidence` 为准。
