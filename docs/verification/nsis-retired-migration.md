# NSIS 0.12.20 旧文件恢复

从已登记的 x64 0.12.20 原位交互式升级到 0.12.23 时，安装器会在新文件放置完毕后核对旧安装登记。匹配固定发行清单的文件会进入可选检查。同一原生窗口显示恢复目录与文件复选项，默认全不选。勾选后可以一次提交，选择「全部保留」或关闭窗口会取消整次移动。完成后同窗口显示每个所选项的结果和失败原因。

候选识别依赖旧版登记、固定相对路径、普通单链接对象、大小与官方文件 SHA-256。内容相同的用户替换文件也可能是候选，因此候选默认不勾选。选择后会复核登记、安装目录和上级目录身份、文件身份与内容。打开列表时不会持续持有目录或文件句柄。仅以同卷句柄重命名移动匹配对象。恢复目录位于安装目录旁，保留原相对路径，且独立于卸载清单。用户可以在资源管理器中将文件移回原有路径，若已有同名文件则按需选择保留的位置。

静默安装、ARM64、登记不匹配、内容修改、不同相对路径的同名文件、无法固定的目录和对象均保留。现有安装器仍按当前发行清单卸载。历史版本未记录文件级归属，升级时不能补认领。以后若加入版本化收据，应从确实创建文件的那一刻记录安装目录和文件身份，与下次升级的当前对象逐项验证，并保留没有安全证据的项。[既有边界与十项发行证据](https://github.com/qing-yi-5427/qing-zip/pull/21)

## 托管验证

工作流 `Hosted NSIS retired-file migration` 仅使用一次性 GitHub 托管 Windows x64。对官方 v0.12.20 setup 和便携 ZIP 做固定 SHA-256 校验，再构建候选安装器。测试通过实际 NSIS 与确认窗口，覆盖静默、在盘根下自定义安装后勾选并取消、以及单页勾选迁移。检查同字节但不同文件身份的替换、预览后改动或被其他进程占用而安全保留的选中项、同名用户文件、原 ZIP、重复升级、卸载后保留及恢复原位置。收据同时保存真实安装页、候选、勾选和结果截图。证据以 [对应 PR 的托管检查](https://github.com/qing-yi-5427/qing-zip/pull/27/checks) 中 `nsis-retired-migration-evidence` 为准。
