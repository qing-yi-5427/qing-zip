# 普通 ZIP 工作空间采样

[托管实测 run 45118622721](https://github.com/qing-yi-5427/qing-zip/actions/runs/45118622721) 的两个独立 Windows x64 runner 均完成；本地没有挂载 VHD。固定 96 MiB VHD 上的 NTFS 分区容量 99,545,088 字节。基线为 `51a68cc32bafcd535eac6cef8eee5169a54adcbe`，候选为 `e9eeecd414fa7379fc959967fb1645ced24eeb62`，均使用对应源码的加固便携包。二进制、产物、卷标识、清理结果和逐轮数据见 [基线](baseline.json)、[基线卷](baseline-vhd.json)、[候选](combined.json)、[候选卷](combined-vhd.json)。VHD 均已卸载，backing 文件已删除。

使用 16 MiB 固定合成内容，ZIP 为 store、单线程；创建与覆盖提取各预热一次后测五轮。提取开始时目标已有等长旧文件，另有无关哨兵。每轮检查来源、归档、旧目标和输出的哈希，以及哨兵与输出目录；输出成员与来源相同。操作后的隔离临时目录均无文件。创建完成后的卷净增均为 16,781,312 字节；覆盖提取完成后净增均为 0（旧目标已占用空间）。

| 操作 | 基线五轮采样增长范围（字节） | 候选五轮采样增长范围（字节） |
| --- | ---: | ---: |
| 创建 | 16,781,312 | 16,781,312–16,846,848 |
| 覆盖提取 | 16,777,216–27,303,936 | 21,020,672–32,542,720 |

目标采样间隔为 5 ms，五轮中实测最大间隔分别为基线 19.225 ms、候选 19.1 ms。**采样到的最高占用只是实际峰值下界**，短暂峰值可能未被捕捉；尤其覆盖提取波动较大。两组使用独立 runner（CPU 型号和缓存状态不同），不能将这组差异视作产品性能回归或改善。未测其他格式、尺寸和文件系统。

常态空间测量与同一作业的满盘断言分别记录状态：本次两组常态测量和满盘创建/覆盖提取断言均通过。先前 run 45117557225 的候选组等待加固构建超时，在创建 VHD 前阻塞，不是产品失败。此 PR 只增加基准与证据，不修改产品行为。

复跑在 GitHub Actions 的 `Disposable Windows ZIP disk capacity` workflow 上使用本分支手动触发；脚本仅接受指定仓库的 GitHub 托管 Windows x64，验证归档构建来源及 VHD 身份后才执行。
