# 主菜单的启动与内存对照

2026-11-23 · Windows 11 x64 build 26300，Ryzen 7 9800X3D，48 GiB，150% 显示缩放。以本地 0.12.23（`0cc51aa`）的 Release GUI 为基线。两组对照都在同一份便携目录副本内交替放入 GUI，CLI、worker 与运行时相同。每次从新进程、新 WebView2 配置打开空白首页，文件系统缓存已经预热。

从启动进程计到驱动观测到首页主操作可见、再经过两个动画帧。驱动查找调试端点的轮询间隔是 100 ms，因此这项数据适合发现明显等待，不宜用来宣称细小的启动提速。首页和菜单打开后各等待一秒，对应用及当时所有后代进程的 private bytes 求和。样本均包括 7 个进程。每版一次预热，随后各 5 次，前后两版交替运行。[全部逐次数据](../../assets/evidence/menu-launch-series.json)

| 最终配对测量 | 原版中位数（范围） | 最终方案中位数（范围） |
| --- | ---: | ---: |
| 首页就绪，ms | 569.2（561.1–584.2） | 469.0（459.7–559.5） |
| 首页进程树私有内存，MiB | 215.50（213.42–215.56） | 216.46（215.59–218.01） |
| 菜单打开时，MiB | 223.28（221.62–223.71） | 226.13（224.56–227.71） |
| 各次从首页到打开菜单的增量，MiB | 8.14（7.77–8.21） | 9.67（8.97–9.86） |

最先尝试的 16 px WebView 背景模糊在独立的五次配对中将打开菜单的增量从 8.09 MiB 提高到 14.80 MiB。最终采用原生窗口材质上的静态半透明渐变与细边线，保留的增量差约为 1.53 MiB。浅色菜单从触发到两个动画帧的中位数在两轮实测中为 15.0 与 15.2 ms，原版为 15.1 与 15.3 ms。屏幕合成和 GPU 显存、低配置设备、系统重启后的磁盘冷读尚待测量。[实机截图与帧数据](../../assets/evidence/fluent-menu/README.md)

## 复跑

在两套构建之间使用同一套便携依赖、相同的可执行文件名和相同的前台显示条件。需要 Python、`websockets` 和 `psutil`。关闭已有的 qing-zip 窗口。每次使用一个新的收据目录，由脚本另行创建独立的临时应用配置。

```powershell
python scripts/fluent-menu-evidence.py --exe <便携目录>/qing-zip.exe --out <本次收据目录> --launch-sample
```
