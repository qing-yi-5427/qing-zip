# 内层 ZIP 恢复摘要与连续编辑

恢复列表按文件身份和提交时的元数据筛选。另存时再次固定同一工作副本，验证其完整内容后才复制。早期已登记记录没有 `digest` 字段，按 SHA-256 读取。新记录的 `digest` 为 `blake3`，同时覆盖新会话的初始工作副本、已提交副本与逐层写回校验。公开文件校验算法和对外发布的 SHA-256 清单不受影响。当前支持普通未加密单卷 ZIP 的已登记编辑。进程在登记完成前结束或系统清理临时文件后，恢复入口可能没有该副本。

## Windows x64 真实窗口

对照为 #36 的 `03ee431`、采用 SHA-256 恢复的 `b5a6e13`，以及采用 BLAKE3 的 `968ccd7`。使用同一 `obz.exe`、`obz-worker.exe` 和逐项哈希一致的 65 个运行时文件。每组预热一次，再用不同顺序运行五组配对，全部使用固定种子的临时存储 ZIP。打开从真实双击到目标成员渲染，改名从真实保存名称到新名称渲染。合计在每组内逐次相加。每代检查成员内容、未修改大文件的 SHA-256、登记的版本和原外包 SHA-256。连续组在同一个已打开的内包内改名三次。[原始窗口计时](paired-timing.json)

| --- | ---: | ---: | ---: | ---: | ---: |
| 4 MiB 打开 | 87.0 | 87.6 | 89.5 | −0.1 [−29.4, +9.1] | +1.6 [−4.4, +4.5] |
| 4 MiB 首次改名 | 111.7 | 121.3 | 115.6 | +2.0 [+1.2, +27.9] | −5.7 [−12.7, +9.1] |
| 4 MiB 打开及首次改名 | 200.1 | 210.5 | 202.5 | +1.8 [−28.2, +37.0] | −4.6 [−8.6, +4.7] |
| 64 MiB 打开 | 164.6 | 160.8 | 141.8 | −22.8 [−26.6, −10.2] | −15.5 [−33.2, −11.1] |
| 64 MiB 首次改名 | 219.3 | 255.0 | 234.4 | +16.0 [+0.5, +31.1] | −18.0 [−30.7, −6.6] |
| 64 MiB 打开及首次改名 | 386.3 | 418.6 | 375.7 | −10.6 [−22.3, +20.9] | −33.5 [−63.9, −17.7] |

单位为毫秒。64 MiB 连续组比 #36 每次多约 15 至 20 ms。花费包括读取实际提交状态的完整摘要并持久登记。SHA-256 组的第一组连续样本耗时明显高于其余四组，原始回执保留了该样本。本机数据是单台 Windows x64 的合成存储包结果，未推断 ARM64 或其他磁盘的耗时。

同机的单线程文件分段微测每组八轮并交错执行。256 KiB 缓冲的 64 MiB 读取加摘要中位为 SHA-256 31.75 ms、Windows CNG SHA-256 32.05 ms、官方默认 BLAKE3 11.57 ms。纯 Rust 特性另测为 19.85 ms。4 MiB 的默认 BLAKE3 为 0.73 ms，同轮 SHA-256 为 2.00 ms。x64 发布构建保持原有 PE 加固检查，GUI 体积增加 22,528 字节，DLL 导入集合一致。[哈希原始计时](hash-timing.json)

## 复跑窗口比较

Windows 上准备三份干净便携目录，三套只替换待测 `qing-zip.exe`，提取核心、worker 与运行时用同一份。使用与项目 `scripts/build-hardened.ps1` 一致的发布配置。安装 Playwright 与 pywin32 Python 依赖，确保没有处于运行状态的 qing-zip，然后执行：

```powershell
python docs/verification/round5/nested-recovery/measure.py `
  --driver scripts/check-nested-multi-layer.py `
  --baseline <稳定版GUI> --sha-recovery <SHA恢复版GUI> --candidate <BLAKE3恢复版GUI> `
  --pairs 5 --out <独立结果目录>
```

计时脚本使用 Win32 私有桌面和独立应用配置，不打开资源管理器的另存窗口。真正的强退、旧索引及系统另存在一次性托管机独立复跑。
